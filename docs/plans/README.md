# Implementation plans

Create a plan only when work spans multiple components, changes a trust boundary, or cannot be safely completed in one focused pass.

Use this compact structure:

```markdown
# Outcome
One observable result.

## Scope
Included and explicitly excluded work.

## Approach
Ordered implementation slices with affected boundaries.

## Verification
Commands, scenarios, and failure cases that demonstrate the outcome.

## Decisions or follow-ups
Durable decisions to record and intentionally deferred work.
```

Delete obsolete plans or mark their outcome when the work is complete. A plan is not a second backlog.
